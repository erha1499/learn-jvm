# 单元四 对象：创建、内存布局与访问

本单元的核心：new 一个对象要经过五步，但最常走的那条路，只是在线程自己的 **TLAB** 里把指针往后挪一下。对象在内存里是“**对象头 + 字段 + 对齐填充**”，总大小按 8 字节对齐。

**学完这个单元，你能：**

- 说出 new 一个对象的五个步骤，以及多个线程同时分配时，JVM 怎么避免抢到同一块内存。
- 算出一个简单对象占多少字节，说清对象头里存了什么。
- 说清一个引用是怎么找到堆里的对象的。

单元三讲了类怎么加载进来，本单元讲用这个类创建对象：先拆开 new 的五步（4.1），再看并发分配的难题和 TLAB（4.2），然后打开对象看它的内存布局（4.3），最后看引用怎么找到对象（4.4）。

## 4.1 new 一个对象的五步

先看 `new` 编译成了什么。`examples/NewObject.java` 里有一行 `NewObject o = new NewObject(42);`，`javap -c` 输出：

```text
0: new           #8                  // class NewObject
3: dup
4: bipush        42
6: invokespecial #13                 // Method "<init>":(I)V
9: astore_1
```

一行 Java 代码，在字节码里被拆成了两步：`new` 指令负责“造出一个空对象”，`invokespecial <init>` 负责“执行构造方法”。展开来是五步：

1. **类加载检查**：去常量池找到这个类的符号引用，检查类是否已经加载、初始化过。没有就先走一遍单元三的流程。
2. **分配内存**：对象需要多大，在类加载完成后就确定了（4.3 节），JVM 要在堆里划出这么一块。
3. **初始化零值**：把这块内存里的字段全部设成 0、false、null。所以**成员变量不赋值也能用**，而局部变量不赋值就用会编译报错。
4. **设置对象头**：写入 Mark Word（哈希码、GC 年龄、锁状态）和类型指针（指向这个对象是哪个类）。
5. **执行构造方法**：按程序员写的代码给字段赋值。

前四步由 `new` 指令完成，第五步由 `invokespecial` 完成。两步之间，对象已经存在、字段却都是零值，这就是“半初始化对象”。多线程下如果引用在构造方法执行完之前就被别的线程看到，就会读到零值，这正是双重检查锁单例要加 volatile 的原因（见 [learn-juc](https://github.com/erha1499/learn-juc) 单元二）。

**分配内存有两种方式**，取决于堆是否规整：

- **指针碰撞**：用过的内存在一边，空闲的在另一边，中间放一个指针当分界线。分配就是把指针往空闲那边挪一段对象大小的距离。
- **空闲列表**：用过的和空闲的内存交错在一起，JVM 维护一张“哪些块空闲”的列表，分配时找一块够大的。

堆是否规整，又取决于垃圾收集器回收后会不会整理内存（单元六）。Serial、Parallel、G1 这些会整理的收集器都用指针碰撞。

## 4.2 并发分配：CAS 与 TLAB

指针碰撞有个问题：两个线程同时 new，都读到同一个指针位置，就会分到同一块内存。JVM 有两种办法：

- **CAS + 失败重试**：用 CAS（先比较再交换的原子指令）挪指针，失败就重读重试。正确，但所有线程都在争同一个指针。
- **TLAB（Thread Local Allocation Buffer，线程本地分配缓冲区）**：每个线程先从 Eden 里批量领一小块内存，专属自己。平时 new 对象只在自己的 TLAB 里挪自己的指针，**完全不需要同步**。TLAB 用完了，再用 CAS 去领一块新的。

TLAB 就像每个人先从公共纸箱里领一叠便利贴：领的时候要排队，平时写一张撕一张，只动自己手里那叠。

TLAB 默认开启。`examples/TlabBench.java` 让 4 个线程各分配 2000 万个小对象，对比打开和关闭 TLAB 的耗时（JDK 17 实测，每种跑三轮）：

| 配置 | 第 1 轮 | 第 2 轮 | 第 3 轮 |
| --- | --- | --- | --- |
| 默认（TLAB 打开） | 149 ms | 136 ms | 121 ms |
| `-XX:-UseTLAB` | 6375 ms | 6324 ms | 6356 ms |

关掉 TLAB 后慢了约 50 倍，这还只是 4 个线程。所以 new 一个小对象的典型代价，就是在 TLAB 里挪一下指针，加上把内存清零，非常便宜。

## 4.3 对象的内存布局

一个对象在堆里分成三部分：

| 部分 | 内容 | 大小（64 位 JVM，默认开启压缩指针） |
| --- | --- | --- |
| 对象头 | Mark Word：哈希码、GC 分代年龄、锁状态 | 8 字节 |
|  | 类型指针：指向方法区里的类元数据 | 4 字节 |
|  | 数组长度（只有数组有） | 4 字节 |
| 实例数据 | 各个字段，JVM 会重新排列顺序 | 看字段 |
| 对齐填充 | 补齐到 8 的倍数 | 0 到 7 字节 |

Mark Word 里的 GC 年龄只有 **4 个比特**，最大能表示 15，所以对象最多熬过 15 次 GC 就进入老年代（6.3 节）。锁状态怎么记录在 Mark Word 里，见 learn-juc 单元三。

**亲手量一量**：`examples/FieldLayout.java` 用 `Unsafe` 读出每个字段在对象里的偏移量。类声明为 `byte b; long l; int i; Object o;`，JDK 17 实测：

```text
源码里的声明顺序：byte b; long l; int i; Object o;
  b 的偏移量 = 24
  l 的偏移量 = 16
  i 的偏移量 = 12
  o 的偏移量 = 28
```

字段没有按声明顺序摆放：对象头只有 12 字节，后面那 4 字节的空隙正好塞进 int；long 要 8 字节对齐，放在 16；剩下的 byte 和引用放在后面。整个对象是 12 + 4 + 8 + 1 + 3（空隙）+ 4 = 32 字节。

`examples/agent/ObjectSize.java` 用 `Instrumentation.getObjectSize` 直接量对象大小（需要打成 Java Agent 运行，方法见 `examples/README.md`）。JDK 17 实测：

| 对象 | 大小 | 怎么算的 |
| --- | --- | --- |
| `new Object()` | 16 字节 | 对象头 12 + 填充 4 |
| `Integer` | 16 字节 | 对象头 12 + int 4 |
| `Long` | 24 字节 | 对象头 12 + long 8 = 20，补齐到 24 |
| 有两个 int 字段的 Point | 24 字节 | 12 + 4 + 4 = 20，补齐到 24 |
| 上面那个 byte、long、int、Object 的类 | 32 字节 | 见上面的偏移量 |
| `new int[0]` | 16 字节 | 对象头 12 + 数组长度 4 |
| `new int[3]` | 32 字节 | 16 + 12 = 28，补齐到 32 |
| `new long[3]` | 40 字节 | 16 + 24 |

一个 `Integer` 为了存 4 字节的值占了 16 字节，再加上集合里存它的那个引用。所以存大量数字时，`int[]` 比 `List<Integer>` 省得多。

**压缩指针**：64 位 JVM 上，一个地址本来要 8 字节。HotSpot 默认开启**压缩指针**，用 4 字节存对象引用和类型指针。因为对象都按 8 字节对齐，地址的最低 3 位永远是 0，4 字节（32 位）的值左移 3 位，就能表示 32GB 的范围。所以：

- 堆小于约 32GB 时，压缩指针自动开启。
- 堆一旦超过 32GB，压缩指针失效，每个引用变回 8 字节，同样的数据占的内存明显变多。**把堆从 31GB 调到 33GB，能装下的对象可能反而更少。**

用 `-XX:-UseCompressedOops` 关掉压缩指针再量一次：上面那个四字段的类从 32 字节变成 40 字节（引用从 4 字节变成 8 字节），一个 String 对象从 24 字节变成 32 字节。

## 4.4 对象的访问定位

栈帧里的引用怎么找到堆里的对象？有两种做法：

| 方式 | 引用里存的是 | 好处 |
| --- | --- | --- |
| 句柄 | 句柄池里一个句柄的地址；句柄再分别指向对象数据和类型数据 | GC 移动对象时只改句柄，引用本身不用改 |
| 直接指针 | 对象的地址，对象头里有类型指针 | 少一次间接访问，速度快 |

HotSpot 用的是**直接指针**。对象访问极其频繁，省一次间接访问很划算；代价是 GC 移动对象后，要把所有指向它的引用都改掉。

## 面试这样说

**问：说一下对象的创建过程。**

> 分五步。先做类加载检查，没加载就先加载类；然后分配内存，堆规整就用指针碰撞，否则用空闲列表，并发安全靠 CAS 重试和 TLAB，TLAB 是每个线程在 Eden 里预先领的一小块私有缓冲区，在里面分配不用同步；接着把内存清零，所以成员变量有默认值；然后设置对象头，写入 Mark Word 和类型指针；最后执行构造方法。前四步对应 new 指令，最后一步对应 invokespecial 调用 `<init>`。

**问：一个 Object 对象占多少字节？**

> 64 位 JVM 默认开启压缩指针时是 16 字节：Mark Word 8 字节，类型指针压缩后 4 字节，对象头共 12 字节，再按 8 字节对齐补 4 字节。对象由对象头、实例数据和对齐填充组成，数组还多一个 4 字节的长度。堆超过 32GB 时压缩指针失效，引用和类型指针都变成 8 字节，对象会变大。
