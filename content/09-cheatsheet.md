# 附录 高频面试题速查表

这张表是各单元「面试这样说」的压缩版，面试前快速过一遍：先用一句话答出框架，追问时再展开成单元末尾那段口述；答不上来就回到对应单元重读。

| 问题 | 一句话答法 | 单元 |
| --- | --- | --- |
| JDK、JRE、JVM 的关系 | JVM 运行字节码；JRE = JVM + 核心类库；JDK = JRE + 编译器和诊断工具 | 一 |
| 栈帧里有什么 | 局部变量表、操作数栈、动态链接、返回地址；前两者大小编译时确定 | 一 |
| `i = i++` 为什么不变 | iload 先压旧值，iinc 改局部变量表，istore 再把旧值写回 | 一 |
| StackOverflowError 和什么有关 | 栈大小（-Xss）和栈帧大小；多半是递归缺少结束条件 | 一 |
| 程序计数器为什么私有 | 线程切换后要知道从哪条字节码继续；唯一不会 OOM 的区域 | 一 |
| 为什么既有解释器又有 JIT | 解释器启动快，JIT 执行快；只编译热点代码，C1 快速编译、C2 激进优化 | 一 |
| JVM 内存区域 | 私有：程序计数器、虚拟机栈、本地方法栈；共享：堆、方法区；另有直接内存 | 二 |
| 堆和栈的区别 | 栈存栈帧、线程私有、随方法弹出；堆存对象、线程共享、由 GC 回收 | 二 |
| 栈里存对象还是指针 | 基本类型存值，对象存引用；对象本身和它的字段都在堆里 | 二 |
| 为什么用元空间替代永久代 | 永久代大小难定、易溢出；元空间用本地内存，默认不限；合并 JRockit | 二 |
| MetaspaceSize 和 MaxMetaspaceSize | 前者是首次触发 GC 卸载类的阈值（会动态调整），后者是上限 | 二 |
| 字符串常量池在哪 | JDK 7 起在堆里；intern 时池里没有就登记当前对象的引用 | 二 |
| `new String("abc")` 创建几个对象 | 池里没有 "abc" 时两个（字面量一个、new 一个），有就一个 | 二 |
| 直接内存为什么快 | IO 时省一次堆内到堆外的复制；随 DirectByteBuffer 被回收而释放 | 二 |
| 有哪几种 OOM | Java heap space、Metaspace、direct buffer memory、unable to create native thread 等 | 二 |
| 内存泄漏和内存溢出 | 泄漏是没用的对象还被引用着、回收不掉；溢出是申请不到内存；泄漏积多了会溢出，溢出不一定是泄漏 | 二 |
| JVM 内存结构和 JMM 的区别 | 前者讲数据放在哪，后者讲多线程间的可见性规则 | 二 |
| 类加载过程 | 加载、验证、准备（静态变量清零）、解析、初始化（执行 `<clinit>`） | 三 |
| 什么时候初始化类 | new、读写静态字段、调静态方法、反射、初始化子类、主类；编译期常量和数组不会 | 三 |
| 类初始化线程安全吗 | 安全，`<clinit>` 只执行一次，其他线程等待；静态内部类单例靠这一点 | 三 |
| 类加载器有哪些 | 启动类（null）、平台类（JDK 8 是扩展类）、应用类，加上自定义 | 三 |
| 双亲委派 | 先查缓存，再交给父加载器，父加载器找不到才自己 findClass；保证核心类安全、不重复加载 | 三 |
| 怎么打破双亲委派 | 重写 loadClass；SPI 用线程上下文类加载器，Tomcat 先加载自己的类，热部署换加载器 | 三 |
| 同名的类一定是同一个类吗 | 不一定，类的身份 = 全限定名 + 类加载器 | 三 |
| 对象创建过程 | 类加载检查、分配内存、清零、设置对象头、执行构造方法 | 四 |
| 并发分配怎么保证安全 | CAS 重试 + TLAB（每个线程在 Eden 里预领一块私有缓冲区） | 四 |
| 对象内存布局 | 对象头（Mark Word 8 + 类型指针 4）+ 实例数据 + 对齐填充；`new Object()` 16 字节 | 四 |
| 压缩指针 | 引用用 4 字节存，左移 3 位可寻址 32GB；堆超过约 32GB 失效 | 四 |
| 对象访问方式 | 句柄或直接指针，HotSpot 用直接指针 | 四 |
| 对象一定在堆上吗 | 语义上是；C2 对不逃逸的对象做标量替换，不在堆上分配（HotSpot 没有真正的栈上分配） | 四 |
| 怎么判断对象可回收 | 可达性分析，从 GC Roots 出发走不到的就是垃圾；引用计数解决不了循环引用 | 五 |
| GC Roots 有哪些 | 栈中局部变量、JNI 引用、静态变量、常量、锁对象、JVM 内部引用 | 五 |
| 四种引用 | 强：不回收；软：内存不足才回收；弱：下次 GC 回收；虚：回收后通知 | 五 |
| 类什么时候能卸载 | 实例全回收、类加载器被回收、Class 对象无引用，三条同时满足 | 五 |
| 什么是安全点 | 线程只能停在记录了引用位置（OopMap）的地方；STW = 到达安全点 + GC 干活 | 五 |
| 回收算法 | 标记-清除（碎片）、复制（浪费空间）、标记-整理（要移动对象） | 六 |
| 为什么要分代 | 对象大多朝生夕灭；新生代用复制，老年代用标记-清除或整理 | 六 |
| 为什么 Eden:S0:S1 = 8:1:1 | 复制算法只浪费 10%，而不是一半 | 六 |
| 对象什么时候进老年代 | 年龄到阈值（默认 15）、动态年龄判断、Survivor 放不下、大对象 | 六 |
| Young GC 怎么处理跨代引用 | 卡表 + 写屏障，只扫脏卡里的老年代对象 | 六 |
| Full GC 什么时候触发 | 老年代不够、担保失败、元空间不够、System.gc()、并发回收跟不上分配 | 六 |
| 有哪些收集器 | Serial、ParNew、Parallel、CMS、G1、ZGC、Shenandoah | 七 |
| 三色标记的漏标 | 黑引用白 + 灰到白的引用全断；CMS 用增量更新，G1 用 SATB | 七 |
| 哪些阶段会 STW | 枚举根总要停；CMS 初始标记、重新标记；G1 的 Young/Mixed GC 和几个短停顿；ZGC 只剩极短停顿 | 七 |
| CMS 的缺点 | 碎片、浮动垃圾、并发失败退化成单线程 Full GC、占 CPU；JDK 14 移除 | 七 |
| G1 的特点 | Region 化、可设停顿目标、优先回收垃圾最多的 Region、整体无碎片 | 七 |
| ZGC 为什么停顿短 | 染色指针 + 读屏障实现并发整理，停顿只处理 GC Roots，通常不到 1ms | 七 |
| G1 和 ZGC 的区别 | G1 平衡吞吐和停顿，复制对象要停；ZGC 并发整理压低停顿，代价是吞吐、内存和分配等待 | 七 |
| 默认收集器 | JDK 8 Parallel；JDK 9 起 G1（非服务器级机器是 Serial） | 七 |
| CPU 飙高怎么查 | top → top -Hp → 线程号转十六进制 → jstack 按 nid 找栈；或对比两次 jstack 的 cpu= | 八 |
| GC 频繁怎么查 | jstat 看 YGC/FGC 增速和老年代水位；Young 多看分配速度，Full 多看泄漏、过早晋升、大对象 | 八 |
| 内存泄漏怎么查 | jstat 看老年代水位 → 类直方图对比或堆转储 → MAT 看支配树和 GC Roots 路径 | 八 |
| 进程内存为什么比 -Xmx 大 | 还有元空间、线程栈、代码缓存、GC 数据结构、直接内存 | 八 |
| 怎么调优 | 先用数据确认是 GC 问题，定目标，一次改一个参数，压测对比 | 八 |
